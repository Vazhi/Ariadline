# Project Charter

## Working name

**Simplified Linguistic English (SLE)** is the working name. The project must perform a naming and acronym review before public release because **SLE** has other established meanings.

## Problem statement

Linguistic writing often mixes observations, theoretical analyses, evidence, qualifications, and citations in the same sentence. Terminology can also change across frameworks or even within one document. These practices can make a claim difficult to interpret, compare, translate, or audit.

## Mission

Develop a [[Controlled Natural Language|controlled form of English]] for clear linguistic description and technical communication.

SLE will help writers:

- state one principal claim at a time;
- use stable terms with explicit definitions;
- distinguish evidence from analysis;
- mark scope, uncertainty, and exceptions;
- present linguistic data consistently;
- produce text that humans can review and software can partially check.

## Intended result

The project will publish:

1. an SLE core standard;
2. one or more [[SLE Profile|profiles]] for different document types;
3. a controlled termbase;
4. authoring and conformance guidance;
5. a test corpus with compliant and noncompliant examples;
6. an open change-control process.

## Success condition

SLE succeeds only if target users understand SLE text more accurately or efficiently than comparable uncontrolled prose **without a material loss of necessary linguistic precision**.

See [[Evaluation Framework]] and [[Quality Metrics and Acceptance Gates]].

## Project principles

- Evidence determines rules; intuition can propose but cannot approve a rule.
- A rule must solve a documented problem.
- A restriction must not remove a necessary distinction.
- The standard must support theoretical plurality.
- Human readability has priority over machine convenience in the core profile.
- Machine-checkable features should be explicit where practical.
- All normative rules require examples, counterexamples, and tests.
