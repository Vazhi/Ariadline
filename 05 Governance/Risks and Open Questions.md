# Risks and Open Questions

## R-01 — Theoretical bias

A controlled term can silently privilege one theory.

**Control:** use project-scoped definitions, profiles, and explicit framework labels.

## R-02 — Precision loss

Shorter sentences can remove dependencies between claims.

**Control:** evaluate content preservation and permit controlled cross-sentence links.

## R-03 — Artificial prose

Excessive restrictions can make text repetitive or difficult to read.

**Control:** test with readers and distinguish core requirements from recommendations.

## R-04 — False objectivity

Standardized wording can make weak evidence appear stronger.

**Control:** require [[Claim-Evidence Matrix|evidence classes]], scope, and limitations.

## R-05 — Tool overreach

A checker can incorrectly reject valid technical writing.

**Control:** classify uncertain detections as warnings and record waivers.

## R-06 — Vocabulary growth

A linguistics-wide termbase can become too large to govern.

**Control:** maintain a small core plus profile and project modules.

## R-07 — Brand ambiguity

The coined name **Ariadline** does not immediately explain the project’s purpose to every reader.

**Control:** pair the name with a descriptive subtitle and maintain a documented naming and intellectual-property review.

## R-08 — English-centered design

Rules based on English academic conventions might disadvantage other rhetorical traditions.

**Control:** include multilingual users and test translation and cross-linguistic usability.

## R-09 — Example standard conflict

Ariadline additions could conflict with established glossing or journal conventions.

**Control:** adopt existing standards where possible and add only clearly scoped requirements.

## Open questions

- Should Ariadline control paragraph structure in v1.0?
- Should evidence-class labels appear in published text or only in authoring metadata?
- Which sentence-length thresholds, if any, have measurable benefit?
- Can a core termbase remain theory-neutral?
- Which rules can a checker verify reliably?
- Should machine-oriented semantics become a separate profile?
- What governance model can represent typological and theoretical diversity?
